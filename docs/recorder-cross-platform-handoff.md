# 录音器跨平台迁移交接（2026-11-06）

本次在既有 `arkme-dsh-client` 和 `arkme-dsh-plugin` 上迭代，未创建独立产品代码库。首批能力：设备识别、容量显示、增量同步、本地播放、另存为 WAV、导入即我。入口为“录音 → 本地设备”。

## 基线与源码

- 2026-11-06 查询正式更新接口，macOS arm64/x64 和 Windows x64 均为 **3.0.27 / vc305**；本机已安装版本相同。
- 客户端功能分支同时包含 `origin/dev` 的 `36a3376f4dde7d3545fa76164acc96de0782d589` 和正式版 `origin/master` 的 `00b7bdbdb0ad40dfa8d35f7c0fe5227d4bc84309`。合并时保留两边的 Windows 更新/安装回归测试。
- 插件功能提交：`9d29e94d71052be6e2ce32c4f2f2829195d1999a`，基于最新 `dev` 的 `9927c3aa56034eda79539d3224729a34ee40f278`，已包含 master v3.0.54。完整协议、缓存、权限和验收合同见插件的 `docs/local-recorder.md`。
- 两个仓库均使用 `codex/ts1106-02-录音器跨平台迁移`，PR 目标为 `dev`；正式合并、版本分配和发布交由同事执行。

## 测试包

`node scripts/build-recorder-test.mjs` 在各目标原生系统上构建。CI 仅监听功能分支，不调用正式版本预留、签名、上传或发布工作流。

测试包由上述现有客户端源码构建，应用名 `arkme Local Test`，保留 3.0.27 / vc305 基线标签。独立应用身份、数据目录 `Arkme Recorder Test` 和凭据命名空间，首次需重新登录；服务连接正式环境，手动“导入即我”会进入真实账号的现有导入队列。测试包不自动更新，内置已固定提交的插件，首次启动不依赖开发机源码路径。

目标为 macOS Apple Silicon、macOS Intel、Windows x64；macOS ad-hoc 签名，Windows 无发布签名，均不作为正式发布产物。包内标记及附带 JSON 清单记录客户端/插件提交、版本、架构及安装包 SHA-256。

测试配置单独为 `@electron/osx-sign@1.3.3` 安装限量文件扫描：原始工具在应用内依赖文件很多时会并发打开文件并触发 EMFILE，提升到 65536 仍可能失败。扫描保留二进制与嵌套应用/Framework 发现，跳过符号链接并使用原签名流程；版本变化会明确失败，要求重新审阅。64 文件描述符限制下的真实目录回归已覆盖该调用路径；正式发布配置不加载此测试钩子。

## 同事发版顺序

1. 审阅两个 PR，按团队流程合入 `dev`，完成 Windows/macOS 真机连接、容量、完整同步、断线续读、离线播放、另存为与真实导入验收。用户已选择稍后做真机验收。
2. 客户端运行时必须包含 `serialport@13.0.0` 及对应系统的 N-API 绑定。先准备兼容运行时，再向用户推广插件；缺少组件时新页面会提示升级并保留已有缓存播放。
3. 插件正式发布仍走既有流程，分配新版本及不可变提交。客户端正式生产目录、锁文件及 fingerprint 应按该已审阅版本同步更新，不能将测试包的 `ARKME_RUNTIME_LOCAL_PLUGIN_DIR` 覆盖用于正式发布。
4. 正式客户端走既有签名、公证、版本预留和发布流程；新版本号及 vc 由该流程统一分配。本次不会占用正式版本，也不会把功能分支测试包切换为线上更新。
