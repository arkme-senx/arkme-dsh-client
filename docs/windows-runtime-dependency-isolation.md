# Windows 运行依赖隔离

开发客户端与自动生成的 Profile 使用 pnpm 的 `packageImportMethod: copy`。Profile 安装命令也显式传入该策略，已有默认 workspace 文件会迁移，自定义 workspace 配置保留。

原因是 Harness 的浏览器热更新按 bundle 的 mtime、ctime 和大小判断版本。共享 pnpm store 的硬链接即使内容未变，也会因其他目录的依赖安装改变元数据；运行中的布局根组件因此可能被卸载，打断导出。本次 Windows 诊断发现 bundle 有 13 个硬链接，文件元数据变化与根组件卸载错误在同一秒出现。

保持官方 Harness 和正常插件热更新机制不变；修复只隔离依赖文件的所有权。Profile 初始化只读取一份 workspace 配置，不在每次启动时扫描或复制全部依赖。

此设置约束后续安装，不会原地拆开旧依赖的共享硬链接。旧开发实例应停止自己的客户端，在独立目录按 copy 策略准备依赖后启动；保留其他实例仍在使用的旧目录，避免删除硬链接时再次影响其元数据。发布包和下载运行环境仍按原有制品摘要、安装和回滚合同交付。
