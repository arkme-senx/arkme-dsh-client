# 桌面会话草稿冷启动恢复

基线：master `71541e83abed3e7fdcbbe0dc959c59894154d136`。本任务工作区 `codex/c20261020-message-sync-run`；插件配套 `codex/c20261020-message-sync-repair`，版本不变。

此前 broker 仅保存在 main 内存；Browser 的普通文本未持久化，localStorage 又绑定 Harness 随机端口。修复在既有原生会话桥内保存不透明编辑器快照，插件继续拥有草稿内容、发送清理和并发编辑语义。没有新增 Plugin Host 业务路由，因此 Tools/SDK 不新增入口；UI 与 Client 双向合同适用。

- 原生选择 Profile 目录，按账号分区，原子替换单个 key 文件；冷启动不依赖 Harness 端口。不持久化发送锁或 busy 状态。快速经过 null 账号的切换也会先等此前接受的保存结束，再加载恢复快照；重复模块挂载对每个 WebContents 只保留一个销毁监听器。
- 1000 项 / 32 MiB 总量、2 MiB 单项、64 项异步写队列；过载拒绝确认，不默默淘汰。启动读取有同样的容量检查；损坏文件保持原样，不回假空快照。
- 正常退出、主/子窗口关闭、菜单重启及运行环境重载先请求 Browser flush，等待 40ms 合并编辑窗口和持久化确认。失败保留编辑页；不会跳转错误页丢掉编辑内容。旧插件无 flush 握手时保留兼容行为。
- null 清空凭据保留，避免旧浏览器草稿复活。插件恢复期间的新编辑/清空优先于旧磁盘快照，保留现有跨窗口发送互斥。

## 验证

- 最终全量：`pnpm test --maxWorkers=1 --testTimeout=30000 --hookTimeout=30000`：123 文件 / 1017 用例通过，3 文件 / 14 用例跳过，63.81s。默认 5 秒超时的安装测试曾超时；后续完整运行曾被 SIGKILL 中断，最终完整复跑通过。
- `pnpm build` 通过。`pnpm typecheck` 仍有既有 `tests/installer-diagnostics.test.ts:20 TS2532`；干净同 SHA 基线独立 worktree 复现，未改无关测试。
- 真实 Electron、生产 preload 和插件真实 auth/composer/sync 模块：带空格目录，5 个独立进程、不同端口，覆盖私聊/群聊/Arko 写入、冷恢复、其他账号、清空、清空后不复活。
- macOS 相同 Node、100 个 32 KiB 草稿、200 次编辑、40ms 间隔：原基线确认 p50/p95 0.018/0.031 ms，新版含原子保存确认 2.022/3.185 ms；事件循环 p95 11.256 → 11.469 ms，最大值 11.543 → 12.190 ms。该样本不代表实际 UI 帧率或线上 SLO，不宣称全局无性能回归。
- Windows/Linux 实机待验收。未发布客户端、插件或动态 Release Set；本机开发运行与不可变插件包安装分别验证。


## 桌面场景验收与依赖

macOS 同一隔离 App Data 下仅输入本地验证草稿；完整退出主进程，重开到不同端口后原文恢复，未发送。随后仅清理验证草稿，原生文件保留 null 凭据，再次完整重开检查为空。

配套插件需要接入可选 `onFlush` 桥，并同步 source/Arko 草稿及处理保存失败。客户端兼容没有握手的旧插件；建议先交付客户端，再交付插件。两仓 PR 不代替运行环境制品与安装包发布。
